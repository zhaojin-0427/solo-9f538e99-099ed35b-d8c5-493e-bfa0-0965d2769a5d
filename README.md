# 口述史馆 · 检索字幕

为口述史馆的单期访谈原片维护「检索字幕」：上传原片 WebVTT 与剪辑 CSV，按剪辑表拼接片段并逐次校订被剪口截断的字幕，发布后按版号下载完整 WebVTT。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>。数据库保存在名为 `oral-history-data` 的卷里，重启容器后已发布版本仍可原样下载。

本地开发：

```bash
python3 -m pip install -r requirements.txt
ORAL_HISTORY_DB=./data/oral_history.db flask --app app.wsgi run --debug
```

## 使用流程

1. **上传单期原片**：一个 WebVTT + 一个剪辑 CSV。
   - CSV 列：`片段号,原片起毫秒,原片止毫秒`（也接受 `fragment_no,start_ms,end_ms`；无表头时按此顺序读取）。
   - 行序即拼接顺序；片段号在表内唯一；**同一原片时段允许被多个片段号重复取用**。
2. **预览**：每一条字幕出现都同时显示对应的**原片时码**与**节选时码**。
   - 整条落在片段内的字幕标记为「整条保留」，沿用正文，无需录入。
   - 被剪口截断的字幕标记为「剪口截断」，须**逐次**录入保留文字或标为删除；同一片段重复出现时各算一次。
3. **发布**：所有剪口出现都处理完才能发布；发布成功后生成新版本号，可下载完整 WebVTT。
   - 成品保留每条原字幕的**时间行设置**（`region:`、`line:` 等），两人同时说话的分区布局不丢失；
     剪口校订、重复剪入、同一时刻的同文字幕，都按各自对应的原字幕取设置。
   - 成品只收录输出字幕**实际引用**的 `REGION` 定义；引用了未定义 REGION 的字幕会在草稿页该条旁标明，
     补齐定义前拒绝发布。
4. **更换剪辑表**：重新上传即建立新草稿，每一次出现都会**重新计算节选时码**。
5. **布局修复件**：旧版详情页可「按源草稿重算并生成修复件」，单独下载。
   - 用该版发布时的**源草稿**重算；只有条数相同、且字幕按原件顺序逐条对得上节选起止和正文，才生成。
   - 每版只留一份修复件；清理源草稿或重启后仍能下载相同字节。
   - 首次生成时若来源缺失、核对不符或生成失败，页面说明原因，不留下修复件。
   - 原下载地址始终返回原件，详情页保留原 SHA-256（修复件单独显示其 SHA-256）。

## 规则要点

- **校订沿用**：仅当「片段号 + 原字幕正文 + 保留的原片范围」三者完全一致时，才沿用上一版校订；剪辑表或原片范围一变即需重新录入。
- **旧页面拒绝**：上传新剪辑表或发布成功后，先前打开的草稿页提交校订/发布会被拒绝（HTTP 409），提示刷新后重新录入。
- **发布原子性**：有未处理剪口、版本冲突或写入失败时不会产生新版本；已发布版本存在 SQLite 中，重启后按版号原样下载。
- **字幕分区与位置**：原片 WebVTT 中的 `REGION` 块与每条字幕的时间行设置会随发布保留；草稿页逐次显示各次出现的设置，引用未定义 REGION 的出现会被标明并阻止发布。
- **修复件核对**：修复件只在重算结果与原件逐条一致时生成，生成后与原件一样持久化在 SQLite 中。
